# custom/

Свои проверки — не апстрим. wscan обходит `nuclei-templates/` рекурсивно, так что
файлы отсюда подхватываются сами по себе, без правок кода. Отдельная папка — чтобы
при будущем обновлении снимка upstream nuclei-templates (см. `MANIFEST.json`) свои
проверки не перепутались с чужими и не потерялись.

## Требования к файлу

- Формат — обычный Nuclei YAML (`http`/`tcp`/`network`/`dns`/`ssl`, `matchers`,
  `extractors`; `flow` для простой оркестрации — тоже поддержан нативно).
- Обязательно поле `id:` — без него `tools/gen_categories.py` пропустит файл
  (не попадёт в индекс, но и не сломает остальное).
- `info.tags` стоит заполнять осмысленно — от них зависит, в какую группу по
  сервису (`match_service` в `gen_categories.py`) попадёт проверка; без
  распознанных токенов всё падает в «Прочие сервисы».
- `code:` — нативный движок исполняет через внешний интерпретатор (opt-in
  `AllowCodeExec`). `javascript:` — встроенный goja + SDK `nuclei/net|ssh|smb|…`
  (см. `internal/engine/js`). `headless:` — по-прежнему недоступен.

## msf-scanner/ (Metasploit codegen)

`custom/msf-scanner/*.yaml` генерируются из Metasploit `auxiliary/scanner`
скриптом [`tools/gen_msf_scanner.py`](../../tools/gen_msf_scanner.py) — без
msfrpcd и без ручного порта модулей. Файлы помечены
`# AUTOGENERATED … do not edit by hand`; отчёт ported/skipped —
`msf-scanner/GENERATED.md`.

Нужен локальный checkout/install Metasploit (по умолчанию
`/opt/metasploit-framework/embedded/framework`).

```sh
cd library
python3 tools/gen_msf_scanner.py
python3 tools/gen_categories.py
```

## msf-exploit/ (Metasploit exploits — курируется вручную)

`custom/msf-exploit/*.yaml` — ручной (не кодоген) порт MSF `exploits/`
модулей, которые не доставляют `Payload` (994 из 2657 — только триггерят
баг и подтверждают эффект, без shell/сессии). Каждый файл верифицирован
против реального исходника MSF-модуля, одно за другим, как
`PROBE_OVERRIDES`/`JS_OVERRIDES` в `gen_msf_scanner.py` — никакой
автогенерации, тут риск выше, чем у пассивного детекта.

Обязательно: `tags: exploit,...`. Это не просто лейбл — это hard-gate в
движке (`domain.Project.AllowExploit`, `internal/engine/exec.go`): без
явного opt-in оператора (TUI → Настройки → предупреждение) шаблон с этим
тегом не выполнится вообще, независимо от протокола (`http:`/`tcp:`/`javascript:`/`flow:`).

Модули с `Payload` (1664 — shellcode/handler/сессия) — отдельная,
пока не начатая задача (Phase 2); `modules/post/` (432, нужна готовая
сессия) — туда же.

## После добавления файлов

Пересобрать индекс категорий (иначе новые проверки не появятся в группировке UI):

```sh
cd library && python3 tools/gen_categories.py
```

Прогнать локальную проверку совместимости без сети и без базы проекта:

```sh
cd .. && go run . audit-library reports/library-audit
```

## Bitrix Full Path Disclosure

`bitrix_full_path_disclosure` требует PHP-диагностику с абсолютным Unix/Windows
путём к PHP-файлу в каталоге `bitrix` и номером строки. HTTP 200 и слово `error`
больше не считаются доказательством. HTTP 500 также допускается. Запросы и ID
сохранены; индексы категорий и продуктов не меняются. Проверка на реальном
Bitrix не выполнялась.
