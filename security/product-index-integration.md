# Индекс продуктов: контракт для wscan

`products.json` — подсказки для оператора на **конкретном хосте и сервисе**.
Индекс не запускает проверки. Код приложения wscan находится вне этого репозитория;
наличие шаблона и его метаданных не устанавливает поддержку движком.

## Генерация и происхождение

Из корня библиотеки, Python 3.9+ и PyYAML 6.x. Использованная версия закреплена
в `tools/requirements-products.txt` (PyYAML 6.0.1). При необходимости установите
зависимость в своём Python окружении: `python3 -m pip install -r tools/requirements-products.txt`.

```sh
python3 tools/gen_categories.py
python3 tools/gen_products.py
```

Генерация полностью локальная. `tools/gen_products.py` читает YAML безопасным
loader, не исполняет Lua, JavaScript, Python или запросы из шаблонов. Повторные
ключи YAML и ошибки UTF-8/разбора попадают в inventory и отчёт проблем. Неизвестный
протокол/порт/требование остаётся неизвестным; обычный порт не подставляется.
`products.json` и отчёт продуктов не содержат времени генерации: одинаковые входы
дают одинаковые байты. `categories.json` сохраняет существующую схему version=1
и поле времени генерации; для products учитывается хеш только его entries.

Курируемые исправления/исключения хранятся в `security/product-rules.json`:
`products` задаёт канонические сущности и vendor-scoped aliases; `overrides`
выбирает точные `paths` или полное совпадение `path_regex`, заменяет products,
применяет `entry` и `category`. Объяснение `reason` обязательно. Порядок правил
существенен: последующее перекрывает предыдущие поля. Пустой products означает
явно убрать продуктовую привязку. `generic_paths` отделяет общие проверки от
неразобранных. `nse_protocol_prefixes` даёт только inferred протокол по принятому
именованию. Правила category применяются обоими генераторами, без изменения
схемы categories. Ручные изменения сгенерированного JSON не сохраняются.

`security/vendor-cves.json` остаётся отдельным ранее подготовленным локальным
срезом: диапазоны и ссылки переносятся оттуда. Этот аудит не обновлял CVE и не
проверял заново свежесть внешних источников. При дальнейшем добавлении внешних
сведений следует сверять первичный advisory и записывать его ссылку в правило.

## Формат schema_version=1

| Поле | Значение |
| --- | --- |
| `source_digest`, `input_sha256` | Хеш инвентаризации и входов генератора; обнаружение устаревшего индекса |
| `inventory[path]` | Каждый YAML/YML Nuclei и NSE: kind, sha256, status; workflow/non_check/parse_error сохраняются |
| `products[key]` | key=`vendor/product`, vendor (может быть null), product, aliases, CPE, family, component, entity_type, checks |
| `checks[id]` | Все разобранные самостоятельные проверки; id=`kind:полный/относительный/путь`, source_id сохранён отдельно |
| `bindings[]` | Несколько products, confidence и basis с источником/правилом/исходным значением |
| `product_status` | bound, generic (курируемое), unresolved (отсутствие установленного продукта) |
| `protocols`, `protocol_confidence`, `protocol_basis` | Протокол **запроса**, не категория сервиса и не протокол уязвимости |
| `request_ports` | mode, values, typical, raw: выбранный сервис, литералы исходника или unknown |
| `affected_service` | protocols, ports, typical_ports, scope и description затронутого сервиса; независимо от запроса |
| `target` | Scope, требования service/product, необходимость пересмотреть фиксированные endpoints; порт не fingerprint |
| `evidence` | kind=version/interface/configuration/direct/unknown, confidence и основание |
| `method_details` | HTTP методы, типы matcher, имена extractor, DSL функции и имена credential placeholders; значения секретов не извлекаются |
| `impact` | Существующая категория и независимые tri-state flags: brute_force, exploit, state_change, dos, external_interaction, authentication_attempts |
| `requirements` | Требования выполнения самой проверки: account, privileges, version, components, user_interaction, исходное описание, аргументы NSE |
| `vulnerability_requirements` | Отдельные предпосылки уязвимости/эксплуатации: версия по HTTP может совпасть без доступности уязвимого компонента |
| `version_constraints` | any_of групп all_of, numeric_release_components, исключение prerelease, локальный источник и ссылки; иначе null |
| `engine` | Требуемые features/modules/binaries; `wscan_support=unknown`, пока приложение не сообщит реальные capabilities |
| `recommendation` | service_candidate, review_required или explicit_exploit_selection; это не разрешение выполнения |

`null` означает «не установлено», `false` — установленное отсутствие конкретного
требования/действия **у запроса проверки**, `true` — установленное наличие.
Тег safe сам по себе никогда не выставляет все флаги false. Severity не определяет
воздействие. Категория `Обнаружение` не отменяет неизвестные флаги. account хранит
строку ограничения, а не булево обещание доступности. Непередаваемая учётная запись
не означает, что любой сервер разрешит запрос без входа.

`explicit` означает наличие metadata/CPE, а не ручную верификацию matcher.
`curated` означает решение по прочитанному исходнику/локальному срезу.
`inferred` — целый токен или условное протокольное именование; это кандидат.
`unknown` не разрешает вывод отрицательного результата. При нескольких vendor и
product без установленного соответствия пары сохраняются как inferred кандидаты.
Несколько bindings могут быть реальными альтернативами, плагином/семейством либо
конфликтом; они перечислены в `product-index-issues.json` и требуют проверки.

Порты `values` при source_literal — **значения из шаблона**, а не разрешение
подключаться на эти порты у любого хоста. `typical`/`typical_ports` — справочная
подсказка. `ports=null` означает, что фактические номера затронутых портов не
установлены. Например SSH может быть настроен на 2222 вместо 22. Исходящий TFTP,
пересылаемый TLS и IPC без выделенного порта отмечены отдельным affected scope.

family/component/entity_type описывают сущность; они не создают наследуемое
соответствие. Windows не равен AD DS; GitLab не равен AI Gateway; RouterOS не
равен SwOS. Алиасы CE/EE объединяют имя базового продукта, но не снимают требований
конкретной редакции из исходного описания. CPE и версии должны относиться к
обнаруженному компоненту, а не к ОС, прокси или соседнему сервису.

## Выбор рекомендаций

1. Вход приложения: host ID, адрес, service ID, фактический порт, transport,
   подтверждённый протокол (включая TLS), продукт/компонент, надёжность fingerprint,
   версия с источником и capabilities движка. Один порт не идентифицирует продукт.
2. Найти точное vendor/product или явный alias. Не переносить продукт на другие
   сервисы хоста и не выводить приложение из nginx/Apache или GitLab из OpenSSH.
3. Проверить протокол **запроса** и scope. HTTP обозначает семейство HTTP(S): TLS
   учитывается фактическим URL выбранного сервиса. tcp — только транспорт; без
   установленного прикладного протокола нельзя считать его совместимым с WinBox.
   JS/code/file/hostrule/global, fixed endpoints и redirects требуют дополнительного
   анализа и контроля адреса. Не переключать порт/хост автоматически.
4. Для ordinary service candidates использовать совместимые explicit/curated
   привязки. Inferred, конфликты нескольких продуктов, неизвестный протокол и
   unresolved показывать только как «требует ручной проверки», с причиной.
   Общие протокольные проверки подбирать отдельно по сервису без продуктового вывода.
5. Надёжную версию сравнивать только с version_constraints: OR между группами,
   AND внутри группы, числовые компоненты выпуска, отсутствующие компоненты как 0.
   Не применять лексикографическое сравнение; beta/rc и неизвестную версию не
   фильтровать как «исправлено». Только явные ограничения из источника допустимы;
   наличие CVE в ID не создаёт диапазон. Backport/редакция/компоненты требуют учёта.
6. Проверить capabilities, аккаунт/права и дополнительные компоненты. Разделять
   prerequisites уязвимости и prerequisites самого HTTP version probe. Требования
   в свободном тексте нельзя автоматически преобразовывать в подтверждённые факты.
7. Применить фильтры воздействия. brute_force выделить исключительно в подбор;
   exploit, dos, state_change и внешнее взаимодействие требуют соответствующего
   явного выбора. Unknown не разрешает считать проверку безопасной или обходить
   фильтры. Авторизованная проверка с одной учётной записью не является подбором.
8. Показать причину, исходник, метод, уверенность и ограничения. Выбор рекомендации
   не запускает шаблон автоматически и не разрешает эксплуатацию.

## Примеры конкретных сервисов

| Обнаружено | Подсказка и ограничение |
| --- | --- |
| GitLab, HTTPS 443 или **9443**, надёжная версия | GitLab HTTP version checks и gitlab-detect: отправлять на выбранный URL/порт; версия → потенциальный риск. AI Gateway не добавлять. GitLab SSH на 2222 с OpenSSH баннером даёт только SSH кандидаты, не GitLab HTTP |
| RouterOS WebFig, HTTPS 8443 | `*-mikrotik-version.yaml` делает GET на 8443; CVE WinBox/SSH/SMB — лишь потенциальное совпадение версии. Не отправлять бинарные пакеты на 8443. CVE-2025-61481 HTTP-only DSL не подходит HTTPS |
| RouterOS WinBox, TCP 8291 или **18291**, протокол подтверждён | `mikrotik-routeros-cve-2024-54772.nse`: активный ограниченный oracle, три пары, попытки аутентификации; требуется кандидат имени. UNKNOWN не означает исправление. Wordlist NSE отдельно только в подборе. Nmap binding к нестандартному выбранному порту должен обеспечить приложение |
| RouterOS SSH 2222 или API 18728 | Только совместимый прикладной протокол. Upstream SSH/API YAML содержит литерал 22/8728: до адаптации исполнителя к выбранному порту требует review; индекс не разрешает сменить порт |
| Kyocera, HTTPS **9091** или **19091** | WSDL address_book: интерфейс без экспорта, не подтверждение CVE. `CVE-2022-1026` отдельно exploit + state_change; SOAP/200 не доказывает успешно созданный экспорт |
| Windows, SMB 445 или **1445** | Windows SMB проверки; общая smb-os-discovery не доказывает DC. Hostrule/smb.get_port может выбрать иной порт: до контроля selected service требуется review |
| LDAP/LDAPS 389/636 или **1389/1636** | Общие LDAP проверки; только LDAP fingerprint не доказывает Microsoft AD DS или роль DC. Не добавлять SMB, Kerberos, RPC, RDP и WinRM автоматически |
| Kerberos 88 или **1088**, REALM установлен | Совместимые Kerberos проверки; `krb5-enum-users` читает словарь, поэтому только категория подбора, не ordinary scan |
| RPC 135 или **1135**, RDP 3389 или **13389** | Раздельные RPC/RDP кандидаты. Динамические RPC endpoints требуют контроля сервиса; Windows fingerprint не гарантирует их доступность |
| WinRM HTTP(S) 5985/5986 или **15986** | winrm-detect — предварительный HTTPAPI/auth fingerprint, review_required; /wsman и 401 не уникальны и не доказывают DC |

Нестандартные порты в таблице — примеры контрактов, не заявление о готовой
поддержке их исполнения текущим wscan. Ограничивающий upstream portrule может
потребовать явного вызова выбранного NSE; hostrule и библиотеки могут самостоятельно
выбирать порты. Индекс это не исправляет.

## Что изменить в приложении

- Загружать schema_version=1, проверять поддерживаемую схему и источник библиотеки;
  сохранять совместимость текущего categories.json, не использовать старое поле
  categories.product как канонический product fingerprint.
- Добавить модель обнаружения host+service+identity+version+confidence и alias resolver.
  Не наследовать идентичность между портами, ОС/ролями и компонентами.
- Добавить сервисный selector с описанными фильтрами, tri-state preconditions и
  capabilities: protocols, matcher/extractor/DSL, JS modules, code/headless/OAST,
  NSE availability. Импорты модулей в исходнике не доказывают наличие реализации.
- Привязать executor к фактическому выбранному адресу/порту, запретить неявный переход
  из literals/hostrule, редиректов и внешних URL. До этого соответствующие кандидаты
  остаются ручными. Обеспечить отдельные gates brute/exploit/DoS/изменение состояния.
- Отображать structured evidence: product/component, service/port, observed fact,
  method, extracted values, source, limitation. Извлекать только именованные
  безопасные значения; не показывать пароли, токены, персональные данные.
- Для version probe показывать: «обнаружена X; опубликованный диапазон CVE совпал;
  потенциально по версии, эксплуатация не подтверждалась». Для WSDL: «namespace и
  операции доступны; экспорт не создавался». Для дифференциального WinBox: размеры
  candidate/control и устойчивость результата; UNKNOWN отдельным состоянием.
- Различать match/no-match/error/timeout/auth-required/parse-error/unsupported.
  Отсутствие находки не означает отсутствие уязвимости или исправление.

## Сопровождение

После изменения шаблонов обновлять оба индекса. Ошибки и неоднозначности не скрывать:
проверить `security/product-index-issues.json` и `product-index-report.md`. Курирование
может уточнять protocol, evidence, requirements и flags только по фактическим
запросам/matcher/Lua и первичным источникам, с reason и стабильным путём. Не писать
новые эксплойты ради заполнения неизвестных полей. Изменённый подписанный upstream
шаблон нельзя выдавать за подписанный оригинал: у локально изменённого Kyocera
CVE-2022-1026 digest сохранён только как upstream provenance, не как действующая подпись.

## Обязательное ограничение каталога внешних целей

Для выбора исполняемых проверок использовать только `categories.entries` и
`products.checks`. `products.inventory` включает сохранённые upstream-файлы:
статус `excluded_scope` запрещает предлагать или запускать их. Правила исключения
находятся в `security/catalog-scope.json`. Нельзя передавать движку весь каталог
шаблонов рекурсивно: локальные аудиты остаются на диске для происхождения.
Удалённый `winrm-detect` относится к отдельному сервису `WinRM`; локальные
WinRM-аудиты не входят в исполняемый каталог.

## Реализованные взаимодействия MSSQL / SMB / LFI

См. [external-audit-implementation.md](external-audit-implementation.md). Это сервисные действия и применение внешнего каталога; подбор продуктовых рекомендаций в TUI остаётся отдельной интеграцией. В курируемых MSSQL правилах `tds` означает Database Engine по TCP, `ssrp` — SQL Browser по UDP; приложению требуется нормализация этих обозначений в сервисы MSSQL/SQL Browser. Стандартный порт не заменяет fingerprint и не разрешает переход на объявленный соседний порт.
