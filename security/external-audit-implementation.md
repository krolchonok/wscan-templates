# MSSQL, SMB и Web LFI: реализованные изменения

Дата: 2026-10-05. Код приложения находится в `../internal`, библиотека — в этом
репозитории. Предыдущий `mssql-import-audit.md/json` сохранён как снимок состояния
до реализации. Этот документ описывает текущий код. Учебные пароли из PDF не
перенесены в словари. Новые эксплойты из статей/PDF не добавлялись.

## Доступ из интерфейса

На выбранном хосте/сервисе нажать `i` → «Взаимодействие».

| Раздел | Действия |
|---|---|
| MSSQL | Выбрать сохранённую учётку, TCP-порт, TLS и проверку сертификата; Enter подключается |
| MSSQL после входа | `1` пользователь/версия/sysadmin, `2` права сервера и базы, `3` базы/TRUSTWORTHY/владелец, `4` таблицы, `5` столбцы, `6` конфигурация, `7` IMPERSONATE сервера и базы, `8` linked servers |
| MSSQL SQL-консоль | Enter или `c` — один SQL batch; `b` — сменить базу через экранированный USE; Esc закрывает сессию; стрелки/PgUp/PgDn прокручивают вывод |
| MSSQL NSE | `n`: явно выбрать `ms-sql-info`, `ms-sql-hasdbaccess` или `ms-sql-tables`; передаётся одна выбранная учётка и текущий порт |
| SMB | `a` переключает запрошенные guest/null identity, `c` выбирает учётку (пароль/NTLM-хеш), `p` задаёт порт; Enter открывает, `d` скачивает, `f` ищет конфигурации в выбранной шаре/каталоге |
| Web LFI | `u` URL выбранного IP/хоста и порта, `p` существующий query-параметр, `v` имя virtual host, `t` проверка TLS; Enter запускает ограниченную проверку |

Вход с одной явно выбранной учёткой в интерфейсе взаимодействия не является
словарным подбором и не требует `AllowCredentialAttack`. Старый интерфейс spray
и post-auth модулей сохраняет этот флаг. Произвольный SQL и проверка чтения через
LFI требуют `AllowExploit`. Фиксированные запросы аудита MSSQL доступны после
входа без этого флага. Настройки xp_cmdshell/CLR/OLE только читаются.

## MSSQL

- Заглушки `IsMssql`, `Connect`, `ExecuteQuery`, `CollectMetadata` заменены.
  PRELOGIN разбирается по TDS; произвольный открытый TCP-порт не считается MSSQL.
- Драйвер `github.com/microsoft/go-mssqldb v1.11.2`, SQL login и Windows NTLM.
  Domain + Username передаются как Windows identity. Для Windows identity
  явно выбран провайдер NTLM; Kerberos/SSO/NTLM-hash для MSSQL не реализованы.
  Пустое имя не трактуется как анонимный SQL-вход или вход от имени машины сканера.
- TCP-порт задаётся явно, Browser discovery не используется для подключения.
  Dialer запрещает server routing на другой хост/порт. JS MSSQL-клиент также
  проверяет адрес относительно выбранных Host/Port.
- В консоли удерживается `sql.Conn`, поэтому USE и SQL session context сохраняются.
  Вход и запросы имеют context timeout; Esc отменяет операцию и закрывает сессию.
- SQL-вывод: до 500 строк в наборе, 8 наборов, около 1 MiB отображаемых значений,
  до 8192 байт в строковом значении; есть признаки усечения. Это ограничение
  отображения, а не разрешение на чтение любых таблиц или гарантия объёма ответа
  на уровне TDS-драйвера. Транскрипт ограничен 512 KiB и очищается от управляющих символов.
- Запросы аудита фиксированы и читают системные представления/функции.
  Ошибка SELECT после успешного входа в новом MSSQL post-auth модуле не записывается
  как ошибочный пароль в lockout ledger. Отсутствие прав, скрытая metadata, NULL и ошибки не являются отрицательным
  результатом проверки уязвимости. IMPERSONATE показывает видимые grants,
  а не рассчитывает весь граф эффективных прав/ролей.
- Обнаружение TCP теперь читает PRELOGIN на 1433 и на неопознанных молчащих
  сервисах, включая нестандартные порты. Для выбранного UDP 1434 добавлен SSRP
  probe; MSSQL Browser определяется по ожидаемым полям ответа. Это отдельный
  UDP-сервис, не разрешение подключаться к объявленным TCP-портам.

## NSE и каталог

- Статический каталог разбирает Lua AST без исполнения: распознаёт множественные
  присваивания `action, portrule, hostrule = Helper.InitScript(...)`, функции-алиасы;
  строки, комментарии и local variables не объявляют глобальные правила.
- Реализованы `nmap.get_ports` и вызов `nmap.set_port_version`; последний является
  no-op относительно постоянного инвентаря приложения. Изменения Lua port.version
  внутри одного запуска остаются доступными скрипту.
- `mssql`/`ms-sql`/`sqlserver` нормализуются в NSE `ms-sql-s`;
  Browser — `ms-sql-m`. Для выбранных сервисов ставится `mssql.scanned-ports-only`.
- Для авторизованного вызова скрипта конфигурация копируется, передаются
  username/password/domain/instance-port. Registry и пароль не переносятся
  автоматически из другого скрипта. Dependencies не запускаются автоматически.
- NSE socket/HTTP requests в приложении ограничены переданным набором хост/порт/
  протокол. Нельзя незаметно перейти к UDP Browser, SMB pipe или другому instance.
  HTTP transport и редиректы проходят эту проверку. Это может намеренно заблокировать
  upstream-метод, которому требуется соседний сервис; результат должен быть ошибкой/неопределённым.
- Наличие правил и успешная компиляция приложения не доказывают работоспособность
  Lua-библиотек на цели. Native NSE имеет ограничения openssl/lpeg/scheduler и
  upstream TDS/TLS; фактические `ms-sql-*` требуют проверки на стенде.
- В локальной библиотеке `categories.json` служит allowlist при перечислении и
  загрузке файлов; отсутствующий путь не возвращается из retained upstream sources.
  Повреждённый индекс не разрешает всё молча. Если индекса нет, остаётся фильтр
  локальных путей/содержимого; для полного ограничения нужен сгенерированный индекс.
- Добавлены guards для cloud/local OS/file/self-contained. Исходники исключённых
  шаблонов сохранены. JS Host/Port привязаны к выбранному сервису; это не утверждение,
  что все внешние бинарники/code и все JS-модули уже имеют универсальный сетевой sandbox.

## SMB

Обычный JS-вызов перечисления прав, проводник и модуль `smb-shares` больше не
создают пробные каталоги. Право записи остаётся неизвестным (`null`/«WRITE ?»).
Legacy Go API `ListSharesWithAccess*` с записью оставлены для совместимости;
новые обычные UI/JS/module пути их не используют.

Для read-only SMB используется уже существующая зависимость
`github.com/oiweiwei/go-smb2.fork v1.0.2`: она позволяет предоставить Initiator.
Добавлен NTLM anonymous Initiator с пустым NT response и однобайтовым нулевым LM
response. Null не подменяется guest при отказе. Требования signing/encryption,
права anonymous RPC и серверная политика могут запретить этот способ. На стенде
он ещё не проверен. UI показывает **запрошенную** identity; фактические server
session flags пока не выводятся, поэтому переход null → guest не заявляется.

Проводник ограничивает список первыми 1000 записями, root read-probe читает одну
запись. Поиск конфигураций: выбранная файловая шара и каталог, глубина до 3, до 200
рассмотренных записей, 20 файлов, 256 KiB на файл, 90 секунд. Имена `.dtsConfig`,
`web.config`, `app.config`, `.env`, `config.ini`, `appsettings*.json`. Простые
connection-string/JSON/INI/XML password/pwd/secret/token/api-key patterns позволяют
отметить наличие секрета. В обычный результат тело конфигурации не попадает вообще;
`secret_present: null` означает, что маленький parser ничего достоверного не установил,
а не отсутствие секретов. Автоматического создания учётки/подбора/импорта пароля нет.
Полный файл можно скачать только отдельным действием оператора.

## Web LFI

Один выбранный endpoint, GET и один существующий query-параметр. Original +
несуществующий контроль + ограниченные traversal probes `/etc/passwd` и
`Windows/win.ini`; максимум 4 запроса. Совпадение требует характерного содержимого,
которого нет в original/control. Ответы до 64 KiB, общий timeout 40 секунд,
10 секунд на запрос. `matched: null` означает неопределённый результат; false
означает только отсутствие подтверждения выполненными запросами. HTTP-ошибки/слишком большой ответ/timeout остаются неопределёнными.
404/500 у несуществующего контрольного файла допустимы; 401/403 не считаются нормальным контролем.

URL должен принадлежать выбранному хосту/порту. Virtual host задаёт Host и TLS SNI,
TCP dial остаётся на выбранном endpoint; редиректы и proxy environment не используются.
Нет UNC/OAST/Responder, автоматического захвата NTLM или офлайн-подбора из PDF.
Подтверждённое чтение сохраняется как finding `native/web-lfi` с описанием факта,
параметра и virtual host, без тела системного файла. Неподтверждение не означает
«LFI отсутствует». POST/body/path fuzzing в этом модуле не реализованы.

## Классификация библиотеки

Курируемые правила в `security/product-rules.json`, генерация через оба генератора.

| ID | Изменение и основание |
|---|---|
| ms-sql-dump-hashes | Эксплуатация/извлечение секретов: SELECT password_hash |
| ms-sql-config | Изменение состояния/эксплуатация: CREATE/INSERT/DROP временной таблицы |
| ms-sql-query | Эксплуатация: операторский аргумент разрешает произвольный SQL; default SELECT не делает весь модуль безопасным |
| ms-sql-xp-cmdshell | Эксплуатация: выполняет OS command, не только проверяет настройку |
| smb-anonymous-access | Перечисление/null identity, только чтение; убрана неподтверждённая привязка к Dionaea |

Для SMB upstream YAML сохранены авторы и ссылка; локальная адаптация описана,
недействительный digest удалён. NSE сетевые запросы не переписывались.

## Выполненная проверка и ручной список для оператора

Выполнены только генерация индексов и `go build ./...`, сборка отдельного бинарника.
Тесты не создавались и не запускались; приложение/шаблоны/NSE/PoC на целях не запускались.
Source hashes и результаты сборки: `external-audit-implementation.json`.

На своих стендах следует проверить:

1. MSSQL SQL login и Windows Domain, неправильный пароль, заблокированную учётку,
   нестандартный порт, TLS с доверенным и self-signed сертификатом; ошибка TLS не
   должна превращаться в успешный вход.
2. Обычный пользователь и sysadmin, скрытые metadata, NULL, denied SELECT;
   после `b` audit должен относиться к выбранной базе; несколько result sets и
   большие таблицы должны показывать усечение.
3. AllowExploit выключен: произвольный SQL не отправляется. Esc на долгом запросе
   закрывает SQL-сессию; новый вход создаёт новую сессию без старого USE/context.
4. NSE с одной учёткой на нестандартном порту: требования native Lua/TLS видны
   как ошибки; попытки обратиться к Browser/SMB/другому instance блокируются.
5. SMB null и guest отдельно, сервер с signing required, доступ к root и denied
   каталог, пароль/NTLM-хеш/Domain. Обычные операции не создают `wscan-*` папки.
   Конфиги из Archetype должны отмечаться без раскрытия пароля в результатах.
6. Web virtual host, negative control 404, Unix/Windows LFI и обычная страница,
   одинаковый marker в исходной странице, oversized/timeout/redirect/TLS errors;
   finding не содержит системный файл.
7. Пересинхронизация каталога: cloud/file/self-contained/local audit не появляются,
   старый excluded путь не загружается; испорченный categories.json даёт ошибку.
