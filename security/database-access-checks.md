# Проверки доступа к базам данных

Локальные исправления wscan отделяют отсутствие аутентификации от успешной проверки пароля.

| Сервис | Проверка |
|---|---|
| PostgreSQL | Отдельно соединение без запроса пароля для роли postgres / базы postgres; пустой и стандартные пароли считаются успешными только после запроса парольной аутентификации |
| MySQL | Настоящая пустая строка пароля для root и пустого имени пользователя; стандартные учётки через Go-клиент |
| Redis | Отдельно INFO без AUTH, AUTH с пустой строкой, стандартные пароли; успешный AUTH обязательно подтверждается INFO |
| MSSQL | Нативные проверки стандартных учёток и пустого пароля sa существующим Go-клиентом |
| CouchDB | Стандартные и пустой пароль через /_session; имя в ответе должно совпасть с проверяемым |
| Elasticsearch | Стандартный и пустой пароль elastic через /_security/_authenticate после отказа анонимному запросу |
| MongoDB, Cassandra, Oracle, Informix | Последовательный адаптер NSE brute.Engine; протокольные драйверы остаются upstream |

Native NSE overrides: pgsql-brute, mysql-brute, ms-sql-brute, redis-brute, mysql-empty-password, ms-sql-empty-password.
По умолчанию не более трёх попыток на пользователя, brute.guesses до 100; учитываются выбранный сервис, ограничение скорости, отмена и таймаут. Пароли скрыты в выводе.
TLS-only сервисы в нативных проверках отклоняются явно: поддержка TLS для этих проверок не заявлена.

Исправлены ложные успехи Informix при несовпадении server-name, Oracle при блокировке/SYSDBA и MongoDB при ошибке транспорта.
Старый elasticsearch-default-login фактически проверяет Kibana и теперь назван соответственно.

Проверки ограничены конкретными ролями, командами и словарями. Они не доказывают отсутствие слабых учёток вообще.
Проверки PostgreSQL, MySQL, Redis, HTTP и последовательного адаптера проверены локальными тестовыми серверами; совместимость всех upstream NSE драйверов с реальными СУБД не проверялась.
