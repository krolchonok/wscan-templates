# MSSQL: аудит импорта и предложения для wscan

> Исторический снимок **до реализации**. Заглушки и часть ограничений ниже уже исправлены; актуальное состояние: [external-audit-implementation.md](external-audit-implementation.md).

Проверены текущие исходники приложения в соседнем каталоге `../internal`, библиотека,
статья [Hackviser MSSQL](https://hackviser.com/tactics/pentesting/services/mssql) как
список тем и обе предоставленные PDF. Основной результат: **новые шаблоны не заменят
отсутствующий TDS-клиент**. Аутентификация и SQL-запросы собственного JS MSSQL-клиента
не реализованы. Граф и FUNCTIONS.md описывают другую/устаревшую конфигурацию движков;
выводы ниже сделаны по прочитанным файлам, не по документации или наличию бинарника.

Доказательства и SHA-256 источников: [mssql-import-audit.json](mssql-import-audit.json).
Статусы — результат статического анализа. Проверки на серверах, загрузка скриптов
в движок, сборка и тесты не выполнялись. Сборка `../wscan` отдельно не исследовалась.

## Что уже включено в библиотеку

В основном покрытии MSSQL: **15 проверок — 3 Nuclei и 12 NSE**. Из NSE одна
широковещательная, 11 предназначены для хоста/сервиса. Все 15 присутствуют в
`categories.json`. HTTP-проверки SSRS/Report Viewer и открытых SQL-дампов являются
другими интерфейсами; их нельзя запускать на TDS только потому, что найден MSSQL.

| Метод | Существующие файлы | Реальное состояние в текущем wscan |
|---|---|---|
| Обнаружение TDS | `javascript/detection/mssql-detect.yaml` | Метод `IsMssql` возвращает true при любом успешном TCP connect: возможен ложный fingerprint; порт задан 1433 |
| SQL Browser | `javascript/udp/detection/mssql-browser-detect.yaml` | Примитивы UDP есть; шаблон посылает 0x02 на 1434 и ищет поля Browser; запуск не проверялся; extractor выдаёт только ServerName |
| Слабые пароли | `javascript/default-logins/mssql-default-logins.yaml` | `Connect` — заглушка; 4 имени × 3 пароля, а не заявленные 7 запросов; пустого пароля в этом YAML нет |
| Версия экземпляра | `ms-sql-info.nse` | Код есть, блокируется распознаванием правил/функций в каталоге |
| NTLM-сведения сервера | `ms-sql-ntlm-info.nse` | Код есть, та же блокировка; это сведения из challenge, не захват ответа учётной записи через Responder |
| Пустой пароль sa | `ms-sql-empty-password.nse` | Код есть, та же блокировка; именованный вход, не анонимный MSSQL |
| Словарный подбор | `ms-sql-brute.nse` | Код есть, правила назначаются множественным присваиванием и не распознаются |
| Конфигурация и linked servers | `ms-sql-config.nse` | Код есть, блокируется; помимо SELECT создаёт/удаляет временную таблицу в SQL-сессии |
| Доступные базы | `ms-sql-hasdbaccess.nse` | Код есть, блокируется; нужна учётная запись |
| Таблицы/столбцы | `ms-sql-tables.nse` | Код есть, блокируется; нужна учётная запись и лимиты перечисления |
| SQL-запрос | `ms-sql-query.nse` | Код есть, правила не распознаются; по умолчанию SELECT версии, произвольный аргумент query меняет воздействие |
| Выполнение команды | `ms-sql-xp-cmdshell.nse` | Код есть, правила не распознаются; по умолчанию выполняет ipconfig /all, не просто читает настройку |
| Хеши SQL-логинов | `ms-sql-dump-hashes.nse` | Код есть, блокируется; выдаёт секреты, несмотря на upstream safe; обычным обнаружением считать нельзя |
| DAC | `ms-sql-dac.nse` | portrule распознаётся, но action через InitScript не проходит CheckSource; это дополнительный административный интерфейс |
| Broadcast discovery | `broadcast-ms-sql-discover.nse` | prerule вне выбранного сервиса, намеренно недоступен в таком запуске |

Файлы NSE находятся в `nmap/scripts/`; YAML — в `nuclei-templates/`.
Словарь YAML: sa/root/admin/test и SqlServer0/SqlServer2021/P@ssw0rd. Эти строки —
кандидаты для подбора, а не универсальные заводские пароли. Пароли из учебных PDF
не добавлялись в словари и не выводятся в этом отчёте.

## Доказанные ограничения приложения

1. [MSSQLClient](../../internal/engine/js/mssql.go): `IsMssql` лишь открывает сокет,
   `Connect` возвращает `authenticated Connect not implemented`, `ExecuteQuery`
   возвращает `not implemented`, `CollectMetadata` выдаёт пустую Version.
   UI credential-проверки MSSQL через [spray.go](../../internal/engine/spray.go)
   вызывают именно эту заглушку и не передают отдельный Domain.
2. [check.go](../../internal/nse/check.go) ищет literal action/function и отдельное
   объявление portrule/hostrule. [output.go](../../internal/nse/output.go) тоже ищет
   отдельное правило. Запись `action, portrule, hostrule = mssql.Helper.InitScript(...)`
   либо `do_action, portrule, hostrule = ...` не распознаётся. Для всех 11 целевых
   MSSQL NSE есть как минимум один такой блокирующий фактор. Это результат
   сравнения исходных деклараций с регулярными выражениями, не запуск Lua.
3. [nseRunner](../../internal/tui/nsescan.go) передаёт только `brute.threads` и
   `brute.delay`, не `mssql.username/password/domain/instance-port/scanned-ports-only`.
   [Runner.Run](../../internal/nse/nse.go) создаёт новый Lua state на каждый скрипт:
   credential registry предыдущего скрипта не переносится; NSE dependencies не
   запускаются этой функцией автоматически. Указание dependencies в файле не
   означает, что подбор будет выполнен или что учётная запись поступит в аудит.
4. [mssql.lua](../nmap/nselib/mssql.lua) умеет делать Browser discovery, искать
   named pipes через SMB и обращаться к экземплярам. Без ограничений скоупа это
   может затронуть соседние сервисы. После исправления загрузки нужно нормализовать
   имена `mssql/ms-sql` ↔ `ms-sql-s` и ограничить сетевые обращения выбранным endpoint.
5. [execJavaScript](../../internal/engine/javascript.go) подставляет целевой Port
   только при отсутствии аргумента. Literal 1433/1434 в MSSQL YAML не заменяется
   выбранным нестандартным портом. Нужна явная привязка запроса к выбранному сервису.
6. В [moduleCatalog](../../internal/engine/modules.go) есть LDAP, SMB и WinRM,
   **модулей MSSQL нет**. Импорт SQL-примеров требует реализации приложения.
7. [catalog.List](../../internal/catalog/catalog.go) обходит исходные файлы и
   применяет categories как метаданные. Отсутствие записи в categories не является
   запретом загрузки. Это расходится с ранее описанным контрактом каталога внешних
   целей: политику `catalog-scope.json` нужно обеспечить и в приложении, включая
   исключение облачного аудита; изменения только индекса не гарантируют исключение.
8. DAST `windows-lfi-fuzz.yaml` есть в Web → Path Traversal / LFI, но HTTP-поле
   `fuzzing` отсутствует в списке поддержанных полей [Parse](../../internal/template/parse.go).
   Не считать наличие категории доказательством исполнения generic LFI DAST.

## Предоставленные PDF и покрытие их цепочек

### Archetype — 16 страниц

[Исходная PDF](../9e4d90d3-11c1-417c-8636-fdbaa096937f.pdf).
Прочитан извлечённый текст всех страниц, отдельно просмотрены скриншоты на с. 4 и 8.

| Страницы | Этап | Что уже есть / что добавить |
|---|---|---|
| 1–3 | MSSQL и SMB; доступ к шару backups | Discovery и SMB browser уже есть в коде; добавить явный режим null/guest и чтение без write probe |
| 3–4 | prod.dtsConfig с connection string | Файл можно читать/скачивать через SMB browser; добавить поиск выбранных конфигурационных файлов и разбор connection strings с маскировкой секретов |
| 6–8 | Windows-аутентификация MSSQL и проверка sysadmin | Реализовать SQL/NTLM-аутентификацию и модуль проверки прав; именно Windows mode нужен для учебной цепочки |
| 8–9 | Проверка и включение xp_cmdshell | Добавить отдельное чтение настройки. Включение изменяет сервер: вынести в отдельное действие эксплуатации |
| 10–12 | Команды ОС, загрузка бинарника, reverse shell | Не включать в обычное обнаружение/авторизованное чтение; отдельный модуль эксплуатации, если позже потребуется |
| 13–16 | winPEAS, история PowerShell, привилегированные действия | Не импортировать как внешние сканерные шаблоны. Это действия после доступа; чтение истории раскрывает секреты |

В текущем [SMB browser](../../internal/engine/js/smb_browser.go) используется guest
с пустым паролем, это не обязательно null-session как в другом клиенте. Обнаружение
списка ресурсов проверяет WRITE через создание и удаление каталога. Аналогично
[ListSharesWithAccess](../../internal/engine/js/smb.go) делает mkdir/remove: UI-проверка
«список шар» сейчас может менять состояние. Ошибка удаления не гарантирует cleanup.
Для первой очереди достаточно list/read без этих операций.

### Responder — 11 страниц

[Исходная PDF](../9e4d90d0-7fc8-426f-a098-51fbd1f03319.pdf).
Прочитан текст всех страниц; просмотрен скриншот с. 9, где ошибка HTTP сопровождается
успешным внешним SMB-взаимодействием. Ошибка HTTP не равна отсутствию такого события.

| Страницы | Этап | Что уже есть / что добавить |
|---|---|---|
| 1–3 | Web/WinRM и virtual host после redirect | Discovery есть; добавить сохранение имени virtual host с привязкой к исходному IP и согласованными Host/SNI, без изменения /etc/hosts и перехода на чужую цель |
| 4–5 | LFI через выбранный page-параметр | Есть библиотека LFI, но generic DAST не поддержан; добавить ограниченную проверку одного выбранного параметра с контролем и узнаваемым содержимым файла |
| 6–9 | UNC-включение → NetNTLMv2 capture | SMB-callback не реализован: [OAST](../../internal/oast/oast.go) наблюдает только HTTP(S), не DNS и не SMB. Нужен отдельный внешний interaction collector |
| 9–10 | Офлайн-подбор пароля | Не функция обычного внешнего сканирования; отдельный инструмент/режим, не запускать автоматически |
| 10–11 | WinRM с известным паролем | Уже есть native WinRM Connect/RunCommand и интерактивный browser/shell. Для этой части новый Evil-WinRM importer не нужен |

NetNTLMv2 challenge-response не следует сохранять как обычный NTHash для pass-the-hash.
В [WinRMClient.Connect](../../internal/engine/js/winrm.go) проверка входа запускает
`exit 0` на цели: это не чистый HTTP fingerprint. Авторизация и shell-действие должны
быть явно различимы оператору. Наличие кода ещё не подтверждает работу на сервере.

## Предлагаемый порядок добавления

### P0 — исправить основания рекомендаций и доступность

- Настоящий TDS PRELOGIN fingerprint; TCP-open оставить только фактом доступности порта.
- SQL Server Browser по выбранному UDP endpoint; извлекать server/instance/version/tcp
  отдельно. Показать объявленный порт как подсказку, не подключаться к нему автоматически.
- Исправить анализ множественных NSE-присваиваний и service aliases, не переписывая
  upstream-скрипты только ради регулярного выражения каталога.
- Передавать выбранную credential и режим аутентификации в NSE; scoped args и лимиты
  применять в сетевом слое. Не запускать зависимости-подбор автоматически.
- Соблюдать catalogue allowlist и общий контракт внешних целей в приложении.

### P1 — MSSQL: авторизованный аудит чтением

Использовать поддерживаемый Go TDS-драйвер вместо заглушек. Кандидат —
[официальный Microsoft go-mssqldb](https://github.com/microsoft/go-mssqldb).
Он документирует SQL/Windows credentials, NTLM/Kerberos providers и явный порт;
при instance без порта может обращаться к Browser. Задать выбранный host:port,
контекст/таймауты, TLS-политику, отключить невыбранные альтернативные endpoints.
Версию зависимости выбрать под текущий Go проекта, не устанавливать latest вслепую.
Kerberos может обращаться к KDC: зависимость и внешние обращения показать отдельно.

Предлагаемые модули (ещё **не реализованы**):

| Имя | Содержание | Ограничение вывода |
|---|---|---|
| `mssql-version` | @@VERSION / SERVERPROPERTY | Наблюдаемая версия, не подтверждение CVE |
| `mssql-permissions` | Текущий login/user, роль sysadmin, эффективные права | Ошибка доступа или NULL — unknown, не «прав нет» |
| `mssql-databases` | Доступные базы, owner, TRUSTWORTHY и chaining | Только доступные метаданные, без чтения пользовательских строк |
| `mssql-tables` | Таблицы и колонки выбранной базы | Ограничить число баз/объектов и размер результата |
| `mssql-config` | xp_cmdshell, CLR, OLE Automation, Ad Hoc options | Только SELECT настроек; не включать функции и не создавать временные таблицы |
| `mssql-impersonation` | Наблюдаемые разрешения IMPERSONATE | Показывать кандидат права; не выполнять EXECUTE AS автоматически |
| `mssql-linked-servers` | Метаданные связанных серверов и RPC settings | Не выполнять OPENQUERY/EXEC AT на соседях |
| `mssql-transport` | Фактическое шифрование текущей сессии и TLS-настройки клиента | Только свойства этой сессии; права и поля могут ограничивать видимость |

Настройки читать через [sys.configurations](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-configurations-transact-sql):
различать value и value_in_use. Права просмотра зависят от версии SQL Server;
отказ — отдельный неопределённый результат. TRUSTWORTHY брать из
[sys.databases](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-databases-transact-sql),
а не из включения xp_cmdshell. Видимость баз ограничена правами.

Каждый модуль: одна выбранная credential и один host+service; фиксированные запросы
чтения, конечные лимиты. Структурированный результат: наблюдение, endpoint, auth mode,
credential ID без секрета, права, метод, ограничения, status success/unknown/error.
Обычный авторизованный аудит отделить от словарного подбора: нынешний общий
AllowCredentialAttack не выражает различия между одной учётной записью и словарём.

### P2 — полезные дополнения из PDF

- SMB list/read без mkdir; null и guest различать в результатах.
- Поиск и разбор выбранных `.dtsConfig`/`web.config`/connection strings: ограниченные
  глубина, размер и число файлов; «секрет присутствует» в обычном выводе. Перенос в
  credentials — отдельное действие оператора, без автоматической проверки на других целях.
- Generic LFI для конкретного URL/параметра; virtual-host mapping для исходного IP.
- Пустой пароль sa и стандартные кандидаты — отдельная категория проверки учётных
  данных с журналом попыток. Секреты учебных стендов не являются стандартными паролями.

### P3 — отдельная эксплуатация/внешнее взаимодействие

При отдельном будущем запросе: ограниченное подтверждение xp_cmdshell, чтение
выбранного файла через SQL, SMB callback/capture с корреляцией события. Требуются
отдельные признаки exploit/state_change/external_interaction и разрешения; RCE нельзя
маскировать как просто «проверку прав». Hashdump требует отдельного секретного хранилища.
Поддержку Pass-the-Hash MSSQL не обещать до реализации транспорта.

Reverse shell, payload upload, persistence, автоматический hash cracking, извлечение
PowerShell history, winPEAS и переходы по linked servers не включать в обычную
сканерную выборку. Это не новые detection-шаблоны для импорта.

## Что изменено этим аудитом

Созданы этот отчёт и JSON с инвентаризацией, статическими ограничениями и хешами.
Приложение, исполняемые шаблоны, словари и категории не менялись. Действия:
чтение PDF/исходников, рендер трёх страниц в /tmp, офлайн-инвентаризация и проверка
первичной документации. Новые модули не импортированы; сетевые цели не проверялись.
